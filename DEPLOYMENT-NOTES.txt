HPM UPDATE - DEPLOYMENT NOTES (2026-11-17 build)

UPLOAD
 1. Back up the live site and database.
 2. Upload everything in this folder over the live site, EXCEPT keep your live
    config/config.php (database password + reCAPTCHA secret key).
 3. Hard refresh (Ctrl+F5) once. File links carry ?v=20261117 so browsers fetch the new CSS/JS.

PRODUCTS MENU = DATABASE (table `categories`)
 - Desktop, laptop, tablet and mobile menus are all filled from api/categories.php,
   which reads `categories` WHERE is_active = 1 ORDER BY sort_order, id.
   Nothing is hard-coded: add, hide, delete or reorder categories in Admin and the
   menu, the Products page sidebar and the product sections all follow.
 - New categories are added at the end. Use the ▲ ▼ buttons in Admin > Categories to reorder.
 - Inactive categories are hidden everywhere on the site. With no active category the
   menu shows "Products will be updated soon."
 - Your database export currently has NO rows in `categories` or `products`.
   Add your categories first in Admin, then add products to them.
   (If you still see old menu items, hard refresh once; old versions kept a copy in the browser.)

OTHER CHANGES
 - Contact form protection: see HPM-CAPTCHA-SETUP.txt.
 - Admin popups on add/edit/delete of products and categories.
 - Speed: unused CSS removed (style.css 966 KB -> ~300 KB, Bootstrap 273 KB -> ~49 KB),
   icon fonts 1.25 MB -> ~27 KB, unused scripts/plugin CSS removed, missing files no longer
   requested (they returned 404 on every page), compression + browser caching in .htaccess.
 - Fixed: Warehouse page image (Warehouse.webp vs warehouse.webp - Linux is case-sensitive).
 - Removed unused scratch files: testfile.html, contact-success-notice.html and old README files.

WHEN YOU EDIT CSS/JS LATER
 - Change the ?v=20261117 number in the HTML files so visitors get the new file.
 - CSS was trimmed to what the pages use. If you add a NEW template component later, its
   styles may need restoring; ask and it can be regenerated.

SECURITY NOTES
 - Table `admins` has a `password_plain` column that stores the admin password in clear
   text. Set it to NULL in phpMyAdmin (UPDATE admins SET password_plain = NULL;) and change
   the admin password afterwards.
